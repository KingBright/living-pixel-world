# Repository workflow

## Branch and publication policy

The repository owner explicitly requested direct commits to `KingBright/living-pixel-world` on `main` for all future authorized iterations. Do not create feature branches or pull requests unless the owner changes that instruction. Read current `main` before publishing, preserve concurrent work, and update the ref without force-pushing or rewriting existing history.

Existing branches may contain unrelated work. Do not delete them or merge their contents merely to clean up branch names without specific authorization identifying the work to retain.

## Project constraints and evidence

All owned core/game/client logic remains Rust. Preserve the original requirements and the distinction between complete source transfer and incomplete product features. No font binaries may be redistributed. Do not invent compiler/test results or dependency lockfile checksums.

An upload is complete only after the final remote main commit and its file tree have been read back and checked. Local commits, Git bundles, and dangling uploaded trees are not completed main pushes. Preserve source integrity and state validation limits honestly.
